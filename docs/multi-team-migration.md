# Multi-team organizations: migration plan

Retrofit plan for adding **organizations → teams** (for example "Team Windows") with isolated data,
team roles and a team switcher, written against the current codebase (commit `408e4dc`).

The prompt template assumed TypeScript, Supabase Auth and UUID keys. This repo differs, and the plan
follows the repo:

| Assumption | What the code actually has | Consequence |
|---|---|---|
| Supabase Auth / `auth.uid()` | Own cookie sessions (`backend/app/auth/__init__.py`), app connects with a direct psycopg2 role | Isolation must be enforced **in Flask**. Supabase RLS keyed on `auth.uid()` would never fire. |
| Separate SQL migrations | Schema is code-managed: `SCHEMA` + `MIGRATIONS` + `INDEXES` in `backend/app/db.py`, run by `init_schema()` on every boot, for **SQLite and PostgreSQL** | Every SQL change below has a mirror in `db.py`, or a fresh DB / local SQLite / the test suite drifts. |
| UUID keys | `INTEGER` identity keys, `TEXT` UTC timestamps | `teams.id` is an integer, timestamps stay `TEXT`. |
| TypeScript | `.jsx` / `.js`, no TS toolchain | Frontend code is JSX. |
| No tenancy yet | `organization_id INTEGER DEFAULT 1` already on 5 tables, `DEFAULT_ORGANIZATION_ID` config, RAG scope cache keyed by org | Reuse the "everything is tenant 1" convention: the default team gets **id 1**, so existing rows are backfilled by a column default with no `UPDATE`. |

## 1. Impact & gap analysis

### 1.1 Table classification

**Team-scoped (gets `team_id`)**: rows a team owns.

| Table | Today | Change |
|---|---|---|
| `documents` | `organization_id` | + `team_id`; `sha256 UNIQUE` → `UNIQUE(team_id, sha256)` |
| `reagents` | `organization_id` | + `team_id` |
| `troubleshooting` | `organization_id` | + `team_id` |
| `agent_uploads`, `agent_runs` | `organization_id` | + `team_id` (`agent_runs` is append-only) |
| `projects`, `experiments`, `datasets` | none | + `team_id` |
| `comments`, `shared_files`, `chat_messages`, `equipment` | none | + `team_id` |
| `audit_log` | none, append-only | + `team_id` **nullable** (sign-ups and password resets have no team) |

**Scoped through their parent (no column)**: `chunks` (→ documents), `experiment_steps`,
`experiment_variables`, `reviews` (→ experiments), `answer_feedback` (→ chat_messages). Each route must
load the parent with a team check first.

**Global / per-user (unchanged)**: `users` (+ `organization_id`), `auth_sessions`, `password_resets`,
`profiles`, `compounds` (reference data, already documented as cross-org), `settings` (stays
org-wide in phase 1).

### 1.2 Gaps found in the current code

1. **Most lookups are by `id` only.** `_get_doc`, `_experiment`, `inventory.get_reagent`,
   `datasets`, `/api/files/<id>` and `/api/chat/<session_id>` all run `WHERE id = ?`. Filtering list
   endpoints is not enough: every get/patch/delete needs `AND team_id = ?`, or Team A can read Team B's
   rows by guessing ids (IDOR).
2. **Some child routes skip the parent check.** `experiments.update_step` and `delete_step`
   (`backend/app/api/experiments.py:109-126`) check `experiment_id = ?` but never call `_experiment()`,
   so a team check added only to `_experiment()` would not cover them.
3. **Retrieval leaks across tenants today.** `api/search.py:25`, `api/chat.py:255` (`/search/vector`)
   and `api/safety.py:49` call `rag.retrieve()` with no `organization_id`. Only the agent path scopes.
4. **Duplicate detection is global.** `rag/engine.py:119` looks up `documents.sha256` across all
   tenants, and the column is globally `UNIQUE`. Once two teams exist, Team B can't upload an SOP that
   Team A already has, and the 409 response returns Team A's document metadata.
5. **Audit tables reject `UPDATE`.** `audit_log` and `agent_runs` have append-only triggers
   (`db.py:340-364`), so `UPDATE … SET team_id = 1` backfills fail. `ADD COLUMN … DEFAULT 1` does not
   fire row triggers and works.
6. **SQLite can't add FK columns with a non-NULL default.** `ALTER TABLE ADD COLUMN team_id INTEGER
   NOT NULL DEFAULT 1 REFERENCES teams(id)` errors when `PRAGMA foreign_keys = ON`. `MIGRATIONS`
   entries therefore carry no `REFERENCES`. The FKs are added on PostgreSQL only, as `NOT VALID` then
   `VALIDATE`.
7. **Identity sequences.** Inserting `id = 1` explicitly into a `GENERATED BY DEFAULT AS IDENTITY`
   table does not advance the sequence, so the next `INSERT` collides. Call `setval` afterwards.
8. **The RAG scope cache is per process.** `RAGEngine._scope_cache` is cleared only in the worker
   that changed the index. That's safe while chunks never change tenant. **Don't allow moving a
   document between teams.** Re-upload it instead.
9. **Browser-loaded URLs can't send headers.** `pagePreviewUrl`, `documentFileUrl` and `fileUrl` are
   used as `<img src>`/links, so the team must also be accepted as a `team_id` query parameter.
10. **Auth-off mode.** With `SMARTLAB_AUTH_REQUIRED=false` (`TestConfig`, local demo) `g.user` is `None`.
    The resolver must fall back to the default team so the existing test suite passes unchanged.
11. **Roles.** `users.role` (`admin`/`member`, first sign-up becomes admin) becomes the **org role**.
    Team roles live in `team_memberships.role` (`owner`/`admin`/`member`/`viewer`). An org admin is an
    implicit owner of every team in the org.

### 1.3 Breaking-change avoidance

- **Old code against the new schema keeps working.** New columns default to team 1, and old queries
  don't name `team_id`. This is what makes "schema first" safe.
- **New code against old clients keeps working.** A request without `X-Team-ID` resolves to the user's
  first team, so a cached old bundle keeps working during the deploy window.
- **Second teams stay off until isolation ships.** Team creation stays behind
  `SMARTLAB_MULTI_TEAM=false` until every route is scoped. Until a second team exists, unscoped
  queries still return the right data.

## 2. Incremental database migration

### 2.1 Supabase SQL: run once, before deploying code

The PostgreSQL migrations are in [`backend/migrations/`](../backend/migrations/). They are idempotent
and tested on PostgreSQL 16 + pgvector 0.8 by `backend/tests/test_rls_policies.py`. Design and
results are in [`supabase-tenancy-rls.md`](supabase-tenancy-rls.md).

| File | Contents |
|---|---|
| `001_tenancy.sql` | `organizations`, `teams` (with `is_default`), `team_memberships`; `users.organization_id` and `users.auth_user_id`; membership backfill; `team_id` on the 13 team tables via `DEFAULT 1` (no `UPDATE`); per-team `sha256` uniqueness; `NOT VALID` FKs; immutable-`team_id` and last-owner triggers |
| `002_rls.sql` | `smartlab_app` role, identity helpers, RLS policies, grants. Enforced only once the app connects as `smartlab_app` |
| `003_indexes.sql` | FK validation and team-leading indexes, `CONCURRENTLY`; run with `psql -f` |
| `004_pgvector.sql` | Optional vector search in PostgreSQL |

After they run, the app's own `init_schema()` finds everything in place and does nothing. Today's
code keeps working on the migrated database (tested).

**Rollback** (before any second team has data): drop the new FKs and indexes, then
`ALTER TABLE … DROP COLUMN team_id`. Dropping the column from `audit_log`/`agent_runs` is DDL, which
the append-only row triggers don't block. Restore `documents_sha256_key` if needed.

```python
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,

    created_at TEXT NOT NULL DEFAULT (datetime('now')),

);
CREATE INDEX IF NOT EXISTS idx_team_memberships_user ON team_memberships(user_id);
"""

}

INDEXES = (

    "CREATE INDEX IF NOT EXISTS idx_experiments_team ON experiments(team_id, updated_at)",

TEAM_TABLES = ("documents", "reagents", "troubleshooting", "equipment", "projects", "experiments", "datasets",
               "comments", "shared_files", "chat_messages", "agent_uploads", "agent_runs", "audit_log")
PG_TENANT_FKS = "".join(
    f"""
DO $$ BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = '{t}_team_id_fkey') THEN
        ALTER TABLE {t} ADD CONSTRAINT {t}_team_id_fkey FOREIGN KEY (team_id) REFERENCES teams(id) NOT VALID;
    END IF;
END $$;

def ensure_default_tenant(conn) -> None:
    """Default organisation and team (id 1, matching the column defaults) and, once, membership of
    the default team for every existing user. Never removes anything."""
    conn.execute("INSERT INTO organizations (id, name, slug) SELECT 1, 'Default organization', 'default' "
                 "WHERE NOT EXISTS (SELECT 1 FROM organizations WHERE id = 1)")
    conn.execute("INSERT INTO teams (id, organization_id, name, slug, is_default) SELECT 1, 1, 'General', 'general', 1 "
                 "WHERE NOT EXISTS (SELECT 1 FROM teams WHERE id = 1)")
    if is_postgres(conn):  # explicit ids don't advance identity sequences
        for table in ("organizations", "teams"):
            conn.execute(f"SELECT setval(pg_get_serial_sequence('{table}', 'id'), "
                         f"GREATEST((SELECT MAX(id) FROM {table}), 1))")
    # One-off: later runs must not re-add someone who was deliberately removed from every team.
    if get_setting(conn, "tenancy_backfilled") != "true":
        conn.execute("INSERT INTO team_memberships (team_id, user_id, role) "
                     "SELECT 1, u.id, CASE WHEN u.role = 'admin' THEN 'owner' ELSE 'member' END FROM users u "
                     "WHERE NOT EXISTS (SELECT 1 FROM team_memberships m WHERE m.user_id = u.id)")
        set_setting(conn, "tenancy_backfilled", "true")
```

## 3. Backend refactoring (Flask)

### 3.1 Why a global resolver plus a decorator

There are about 60 routes across 15 blueprints. A per-route `@require_team_access` that a developer
can forget fails **open**. Instead:

- a `before_request` hook resolves and **verifies** the team for every `/api/` request, and fails
  closed with 403 if none can be resolved;
- `team_id()` raises if it's called without a resolved team, so a missed route errors instead of leaking;
- `@require_team_access("admin")` exists only to raise the **minimum role** on specific routes.

### 3.2 `backend/app/tenancy.py` (new)

```python
"""Team tenancy: the active team for every API request, verified against memberships.

The client names its team in the ``X-Team-ID`` header, or the ``team_id`` query parameter for URLs
the browser loads itself (``<img src>``, file links). That value is a request, not a fact: it is
checked against ``team_memberships`` (or org-admin rights) before ``g.team`` is set. Routes read the
team with :func:`team_id` and never from the request.
"""
from __future__ import annotations

import functools
from typing import Any

from flask import Flask, g, jsonify, request

from .api.common import ApiError
from .db import get_db

TEAM_HEADER = "X-Team-ID"
# Not team data: reachable without an active team.
TEAM_FREE_API = ("/api/health", "/api/auth/", "/api/teams")
ROLE_RANK = {"viewer": 0, "member": 1, "admin": 2, "owner": 3}

# Teams the user may open: explicit memberships, plus every team of their organisation for org admins.
_TEAMS_SQL = (
    "SELECT t.id, t.organization_id, t.name, t.slug, "
    "CASE WHEN u.role = 'admin' THEN 'owner' ELSE m.role END AS role "  # same rule as smartlab.team_ids()
    "FROM teams t JOIN users u ON u.id = ? AND u.organization_id = t.organization_id "
    "LEFT JOIN team_memberships m ON m.team_id = t.id AND m.user_id = u.id "
    "WHERE t.archived_at IS NULL AND (m.user_id IS NOT NULL OR u.role = 'admin')"
)


def user_teams(conn, user_id: int) -> list[dict[str, Any]]:
    return [dict(r) for r in conn.execute(_TEAMS_SQL + " ORDER BY t.id", (user_id,))]


def team_for_user(conn, user_id: int, team_id: int) -> dict[str, Any] | None:
    row = conn.execute(_TEAMS_SQL + " AND t.id = ?", (user_id, team_id)).fetchone()
    return dict(row) if row else None


def team_id() -> int:
    """The verified active team. Raises outside a team-scoped request so a missed route fails closed."""
    team = g.get("team")
    if team is None:
        raise RuntimeError("team_id() used on a request without a resolved team")
    return team["id"]


def organization_id() -> int:
    return g.team["organization_id"]


def require_team_access(min_role: str = "member"):
    """Raise the minimum team role for a route (the resolver already guarantees membership)."""
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            team = g.get("team")
            if team is None or ROLE_RANK.get(team["role"], -1) < ROLE_RANK[min_role]:
                raise ApiError(f"This action needs the team {min_role} role.", 403, code="team_role")
            return fn(*args, **kwargs)
        return wrapper
    return decorator


def init_tenancy(app: Flask) -> None:
    """Register after init_auth(): Flask runs before_request hooks in registration order."""

    @app.before_request
    def resolve_team():
        g.team = None
        path = request.path
        if not path.startswith("/api/") or request.method == "OPTIONS" or path.startswith(TEAM_FREE_API):
            return None
        user = g.get("user")
        if user is None:
            # Only reachable with SMARTLAB_AUTH_REQUIRED off (tests, local demo): one default team, as today.
            g.team = {"id": app.config["DEFAULT_TEAM_ID"], "organization_id": app.config["DEFAULT_ORGANIZATION_ID"],
                      "name": "General", "role": "owner"}
            return None
        raw = request.headers.get(TEAM_HEADER) or request.args.get("team_id")
        conn = get_db()
        if raw is None:
            # Clients from before this release send no header: their first team keeps them working.
            teams = user_teams(conn, user["id"])
            g.team = teams[0] if teams else None
        elif raw.isdigit():
            g.team = team_for_user(conn, user["id"], int(raw))
        if g.team is None:
            return jsonify({"error": "You don't have access to this team.", "code": "team_forbidden"}), 403
        return None
```

Register it in `create_app()`:

```python
    init_auth(app)
    init_tenancy(app)  # after auth: needs g.user
    _register_blueprints(app)
```

CORS: `X-Team-ID` is a non-simple header. Production is same-origin, so there's no preflight. For
the Vite dev server on another origin, allow the header:
`CORS(app, resources=…, supports_credentials=True, allow_headers=["Content-Type", "X-Team-ID"])`.

### 3.3 Team management API: `backend/app/api/teams.py` (new)

```python
"""Teams of the signed-in user's organisation, and team membership."""
from __future__ import annotations

import re

from flask import Blueprint, current_app, jsonify

from ..auth import actor_name, current_user
from ..db import audit, get_db
from ..tenancy import ROLE_RANK, team_for_user, user_teams
from .common import ApiError, json_body, require

bp = Blueprint("teams", __name__, url_prefix="/api/teams")


def _user():
    user = current_user()
    if user is None:
        raise ApiError("Authentication required.", 401, code="auth_required")
    return user


def _team(team_id: int, min_role: str = "viewer") -> dict:
    team = team_for_user(get_db(), _user()["id"], team_id)
    if team is None:
        raise ApiError("Team not found.", 404)
    if ROLE_RANK[team["role"]] < ROLE_RANK[min_role]:
        raise ApiError(f"This action needs the team {min_role} role.", 403, code="team_role")
    return team


@bp.get("")
def my_teams():
    return jsonify({"teams": user_teams(get_db(), _user()["id"]),
                    "can_create": current_app.config["MULTI_TEAM"] and _user()["role"] == "admin"})


@bp.post("")
def create_team():
    user = _user()
    if not current_app.config["MULTI_TEAM"] or user["role"] != "admin":
        raise ApiError("Only organization admins can create teams.", 403)
    data = json_body()
    require(data, "name")
    name = str(data["name"]).strip()[:80]
    slug = re.sub(r"[^a-z0-9]+", "-", name.lower()).strip("-") or "team"
    conn = get_db()
    org = conn.execute("SELECT organization_id FROM users WHERE id = ?", (user["id"],)).fetchone()[0]
    if conn.execute("SELECT 1 FROM teams WHERE organization_id = ? AND slug = ?", (org, slug)).fetchone():
        raise ApiError("A team with this name already exists.", 409, field="name")
    tid = conn.execute("INSERT INTO teams (organization_id, name, slug, description) VALUES (?, ?, ?, ?)",
                       (org, name, slug, data.get("description"))).lastrowid
    conn.execute("INSERT INTO team_memberships (team_id, user_id, role) VALUES (?, ?, 'owner')", (tid, user["id"]))
    audit(conn, "create", "team", tid, f"Created team '{name}'", actor_name())
    conn.commit()
    return jsonify(team_for_user(conn, user["id"], tid)), 201


@bp.get("/<int:team_id>/members")
def members(team_id: int):
    _team(team_id)
    rows = get_db().execute(
        "SELECT u.id, u.name, u.email, m.role, m.created_at FROM team_memberships m "
        "JOIN users u ON u.id = m.user_id WHERE m.team_id = ? ORDER BY u.name", (team_id,))
    return jsonify([dict(r) for r in rows])


@bp.put("/<int:team_id>/members")
def upsert_member(team_id: int):
    """Add an existing account of the same organisation, or change its role."""
    team = _team(team_id, "admin")
    data = json_body()
    require(data, "email")
    role = data.get("role", "member")
    if role not in ROLE_RANK or ROLE_RANK[role] > ROLE_RANK[team["role"]]:
        raise ApiError("You can't grant a role above your own.", 403)
    conn = get_db()
    target = conn.execute("SELECT id FROM users WHERE email = ? AND organization_id = ?",
                          (str(data["email"]).strip().lower(), team["organization_id"])).fetchone()
    if target is None:
        raise ApiError("No account with this email in your organization.", 404, field="email")
    conn.execute("INSERT INTO team_memberships (team_id, user_id, role) VALUES (?, ?, ?) "
                 "ON CONFLICT (team_id, user_id) DO UPDATE SET role = excluded.role", (team_id, target[0], role))
    audit(conn, "member_role", "team", team_id, f"Set {data['email']} to {role}", actor_name())
    conn.commit()
    return members(team_id)


@bp.delete("/<int:team_id>/members/<int:user_id>")
def remove_member(team_id: int, user_id: int):
    _team(team_id, "admin")
    conn = get_db()
    owners = conn.execute("SELECT COUNT(*) FROM team_memberships WHERE team_id = ? AND role = 'owner' "
                          "AND user_id <> ?", (team_id, user_id)).fetchone()[0]
    if owners == 0:
        raise ApiError("A team needs at least one owner.", 409)
    conn.execute("DELETE FROM team_memberships WHERE team_id = ? AND user_id = ?", (team_id, user_id))
    audit(conn, "member_removed", "team", team_id, f"Removed user {user_id}", actor_name())
    conn.commit()
    return "", 204
```

`ON CONFLICT … DO UPDATE` works on both engines (SQLite ≥ 3.24), as `set_setting` already relies on.
Register `teams` in `_register_blueprints`.

**Sign-up** (`api/auth.py`): keep today's behavior in phase 1, where every new account joins org 1
and team 1. After inserting the user, add
`INSERT INTO team_memberships (team_id, user_id, role) VALUES (?, ?, ?)` with
`DEFAULT_TEAM_ID` and `'owner' if role == 'admin' else 'member'`. Invitations into a chosen team
replace this later (`InviteDialog` in `AppShell.jsx` is already a stub waiting for it).

### 3.4 Refactoring existing routes: the patterns

**Pattern A: id lookups get `AND team_id = ?` and return 404** (never 403, which would confirm
the row exists in another team).

```python
# api/experiments.py
from ..tenancy import team_id

def _experiment(exp_id: int) -> dict:
    exp = query_one(
        "SELECT e.*, p.name AS project_name, pr.name AS owner_name FROM experiments e "
        "LEFT JOIN projects p ON p.id = e.project_id LEFT JOIN profiles pr ON pr.id = e.owner_id "
        "WHERE e.id = ? AND e.team_id = ?",
        (exp_id, team_id()))
    if exp is None:
        raise ApiError("Experiment not found.", 404)
    return exp
```

**Pattern B: lists filter, inserts stamp `team_id` from the server, and foreign ids get checked.**

```python
@bp.get("")
def list_experiments():
    sql = ("SELECT e.*, p.name AS project_name, pr.name AS owner_name FROM experiments e "
           "LEFT JOIN projects p ON p.id = e.project_id LEFT JOIN profiles pr ON pr.id = e.owner_id "
           "WHERE e.team_id = ?")
    params = [team_id()]
    if request.args.get("project_id"):
        sql += " AND e.project_id = ?"
        params.append(request.args["project_id"])
    return jsonify(query_all(sql + " ORDER BY e.updated_at DESC, e.id DESC", params))


@bp.post("")
def create_experiment():
```

### 4.2 `src/context/TeamContext.jsx` (new)

```jsx
import { createContext, useCallback, useContext, useEffect, useMemo, useState } from "react";
import { api, setActiveTeamId } from "../lib/api";
import { useApp } from "./AppContext";

const TeamContext = createContext(null);
const storageKey = (accountId) => `smartlab-team:${accountId}`;

function remembered(accountId) {
  try { return Number(localStorage.getItem(storageKey(accountId))) || null; } catch { return null; }
}

/**
 * The teams the signed-in account can open and the active one. Every API call carries the active
 * team (lib/api.js). Switching remounts the app shell (see App.jsx) so no view keeps the previous
 * team's data in memory.
 */
export function TeamProvider({ children }) {
  const { account, toast } = useApp();
  const [teams, setTeams] = useState(null); // null while loading
  const [canCreate, setCanCreate] = useState(false);
  const [activeId, setActiveId] = useState(null);

  const load = useCallback(async () => {
    const r = await api.teams();
    setTeams(r.teams);
    setCanCreate(r.can_create);
    return r.teams;
  }, []);

  const select = useCallback((id) => {
    setActiveTeamId(id); // before state, so the remount's first requests already carry it
    setActiveId(id);
    try { localStorage.setItem(storageKey(account.id), String(id)); } catch { /* private mode */ }
  }, [account]);

  useEffect(() => {
    if (!account) return;
    load().then((list) => {
      const saved = remembered(account.id);
      const pick = list.find((t) => t.id === saved) ?? list[0];
      if (pick) select(pick.id);
    }).catch(() => setTeams([]));
  }, [account, load, select]);

  // The server rejected the active team (membership removed, team archived): fall back to another.
  useEffect(() => {
    const onInvalid = () => load().then((list) => {
      if (list[0]) { select(list[0].id); toast("You no longer have access to that team.", "warning"); }
    });
    window.addEventListener("smartlab:team-invalid", onInvalid);
    return () => window.removeEventListener("smartlab:team-invalid", onInvalid);
  }, [load, select, toast]);

  const activeTeam = teams?.find((t) => t.id === activeId) ?? null;
  const value = useMemo(() => ({
    teams, activeTeam, canCreate, switchTeam: select, reloadTeams: load,
    canEdit: activeTeam ? activeTeam.role !== "viewer" : false,
    isTeamAdmin: activeTeam ? ["admin", "owner"].includes(activeTeam.role) : false,
  }), [teams, activeTeam, canCreate, select, load]);

  return <TeamContext.Provider value={value}>{children}</TeamContext.Provider>;
}

export const useTeam = () => useContext(TeamContext);
```

## 5. Step-by-step migration roadmap

Each step can be deployed and verified on its own, and each is backward-compatible with the step
before it.

| # | Step | Deploy | Verify | Rollback |
|---|---|---|---|---|
| 0 | **Back up.** Supabase → Database → Backups (or `pg_dump`). Note row counts per table. | — | Backup exists | — |
| 1 | **Run `backend/migrations/001_tenancy.sql`**, then `003_indexes.sql` with `psql -f` (section 2.1). RLS (`002`) follows the rollout in `supabase-tenancy-rls.md`. | DB only. The running app is unaffected: new columns default to team 1. | `SELECT team_id, COUNT(*) FROM documents GROUP BY 1` → all `1`; every user has a membership; `pg_constraint` FKs `convalidated = true` | Section 2.1 rollback |
| 2 | **Ship the backend foundation**: `db.py` mirror (2.2), `tenancy.py`, `teams.py`, `audit()` change, signup membership. `MULTI_TEAM=false`. Routes not yet scoped. | Render deploy | `GET /api/teams` → `[General]`; existing UI works unchanged; `pytest` green on SQLite and PG | Redeploy previous commit (schema stays, harmless) |
| 3 | **Scope every route** (3.4, patterns A–G), one blueprint per commit, plus `test_team_isolation.py`. | Render deploy | Isolation tests green; with one team, behavior is identical | Revert commits |
| 4 | **Ship the frontend**: header injection, `TeamProvider`, gate, switcher. | Same Render build (`render-build.sh` builds Vite) | Network tab shows `X-Team-ID` on XHR, SSE and uploads; `team_id=` on image URLs | Revert; the backend still accepts header-less requests |
| 5 | **Pilot.** Set `SMARTLAB_MULTI_TEAM=true`, create "Team Windows", add two test accounts, run the isolation checklist by hand (documents, search, co-pilot, files, activity feed). | Env var + restart | No cross-team rows anywhere | Archive the team (`archived_at`), unset the flag |
| 6 | **Harden.** Make `retrieve(team_id=…)` required, drop `organization_id` writes once nothing reads them, add invite-to-team flow, per-team `settings` if needed. | Normal releases | — | — |

### Ordering rationale

- **Schema before code.** Old code ignores the new columns and inserts get the default, so step 1
  needs no downtime and no coordinated deploy.
- **Scoping before the flag.** Unscoped queries are invisible while only team 1 exists. The flag
  ensures a second team can't exist before every query filters on it.
- **Frontend last.** The backend's header-less fallback (first team) means the old bundle keeps
  working, so the frontend can ship whenever it's ready.
- **Render runs `init_schema()` on boot under an advisory lock.** If step 1 is skipped, step 2 still
  migrates on deploy. Running step 1 manually first keeps DDL locks out of the request path and gives
  you a verification point.
