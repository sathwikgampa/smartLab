# Supabase: team schema, row-level security and vector search

Database layer for multi-team isolation in SmartLab AI. The application-side plan is in
[`multi-team-migration.md`](multi-team-migration.md). This document covers what PostgreSQL itself
enforces.

| File | What it does | Transaction |
|---|---|---|
| [`backend/migrations/001_tenancy.sql`](../backend/migrations/001_tenancy.sql) | `organizations`, `teams`, `team_memberships`; `team_id` on 13 tables; FKs; immutability and last-owner triggers | one, `lock_timeout 5s` |
| [`backend/migrations/002_rls.sql`](../backend/migrations/002_rls.sql) | `smartlab_app` role, identity helpers, RLS policies on every table, grants | one, `lock_timeout 5s` |
| [`backend/migrations/003_indexes.sql`](../backend/migrations/003_indexes.sql) | FK validation, team-leading indexes, `CONCURRENTLY` | none (statement by statement) |
| [`backend/migrations/004_pgvector.sql`](../backend/migrations/004_pgvector.sql) | Optional. `chunk_embeddings` (pgvector, HNSW) and `smartlab.match_chunks()` | one |
| [`backend/tests/test_rls_policies.py`](../backend/tests/test_rls_policies.py) | 28 tests against a real PostgreSQL | — |

**Tested on** PostgreSQL 16.15 + pgvector 0.8.7 (`pgvector/pgvector:pg16`), in a cluster set up the
way Supabase is:

- the table owner is not a superuser;
- `anon`/`authenticated` roles exist with Supabase's default grants;
- `auth.uid()` reads the JWT claim.

The schema under test is the app's real one, built by `create_app()` with demo seed data. All
migrations are applied twice to prove they're idempotent. A mutation check (opening the SELECT
policies to `USING (true)`) makes 8 isolation tests fail, so the tests do detect leaks.

**Not tested:** a real Supabase project (Supavisor, Supabase's exact grants, the SQL editor).
Run the migrations on a Supabase branch or staging project first.

```bash
docker run -d --name smartlab-rls -e POSTGRES_PASSWORD=pw -p 55432:5432 pgvector/pgvector:pg16
SMARTLAB_TEST_PG_ADMIN_URL=postgresql://postgres:pw@localhost:55432/postgres pytest tests/test_rls_policies.py
docker rm -f smartlab-rls
```

### Where the brief and this codebase disagree

| Brief | Codebase | Decision |
|---|---|---|
| RLS via `auth.uid()` | Flask's own cookie sessions. The app connects through psycopg2 **as the table owner, which bypasses RLS**, so `auth.uid()` is always NULL for app traffic. | The app connects as a new non-owner role, `smartlab_app`, and declares the user per transaction with `set_config(…, true)`. Policies also resolve `auth.uid()` through `users.auth_user_id`, so adopting Supabase Auth later needs no policy changes. |
| `gen_random_uuid()` keys | `INTEGER` identity keys everywhere: Flask routes are `<int:id>`, `lastrowid` emulation, the SQLite mirror | Integer keys. Converting every table and FK isn't worth it: guessed ids return nothing under RLS (tested). |
| Timestamps | `TEXT 'YYYY-MM-DD HH24:MI:SS'` UTC, shared with SQLite and the API | Same format in the new tables. |
| GIN on JSONB | No JSONB columns. JSON is stored as `TEXT` and never queried inside | No GIN. The real search hot spot is `ILIKE '%term%'`, so 003 has trigram GIN indexes, commented out until tables pass ~10k rows. |
| pgvector HNSW | Vectors live in a FAISS/NumPy file on Render's ephemeral disk | Optional migration 004. |

## 1. Schema & tables

```
organizations 1───* teams 1───* team_memberships *───1 users *───1 organizations
                      │
                      └──* documents, reagents, troubleshooting, equipment, projects, experiments,
                           datasets, comments, shared_files, chat_messages, agent_uploads,
                           agent_runs, audit_log (team_id → teams.id)
                               │
                               └──* chunks, experiment_steps, experiment_variables, reviews,
                                    answer_feedback (scoped through their parent)
```

The new tables, from `001_tenancy.sql`:

```sql
CREATE TABLE IF NOT EXISTS public.teams (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    organization_id INTEGER NOT NULL REFERENCES public.organizations(id) ON DELETE RESTRICT,
    name TEXT NOT NULL CHECK (length(btrim(name)) BETWEEN 1 AND 80),
    slug TEXT NOT NULL CHECK (slug ~ '^[a-z0-9]+(-[a-z0-9]+)*$'),
    description TEXT CHECK (description IS NULL OR length(description) <= 500),
    is_default INTEGER NOT NULL DEFAULT 0 CHECK (is_default IN (0, 1)),   -- sign-ups join this team
    archived_at TEXT,                                                    -- archived, never deleted
    created_at TEXT NOT NULL DEFAULT to_char(timezone('UTC', statement_timestamp()), 'YYYY-MM-DD HH24:MI:SS'),
    UNIQUE (organization_id, slug)
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_teams_one_default ON public.teams (organization_id) WHERE is_default = 1;

CREATE TABLE IF NOT EXISTS public.team_memberships (
    team_id INTEGER NOT NULL REFERENCES public.teams(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
    role TEXT NOT NULL DEFAULT 'member' CHECK (role IN ('owner', 'admin', 'member', 'viewer')),
    created_at TEXT NOT NULL DEFAULT to_char(timezone('UTC', statement_timestamp()), 'YYYY-MM-DD HH24:MI:SS'),
    PRIMARY KEY (team_id, user_id)
);
```

Design points, each covered by a test:

- **No backfill `UPDATE`.** Existing rows join team 1 through `ADD COLUMN … DEFAULT 1`, which is
  metadata-only on PG 11+. An `UPDATE` would also be rejected by the append-only triggers on
  `audit_log` and `agent_runs`.
- **Today's app keeps working on the migrated database.** A test boots the current code against it,
  creates and deletes a reagent, and checks that the new rows land in team 1.
- **Inserts that omit `team_id` land in the active team.** After 002, the default is
  `COALESCE(smartlab.current_team_id(), 1)`. A forgotten column goes to the active team, never
  silently to team 1. Owner connections, which have no active team, keep the old default of 1.
- **`team_id` is immutable.** A `BEFORE UPDATE OF team_id` trigger enforces it. Rows never move
  between teams; re-create them instead. This also protects the RAG engine's per-process scope cache.
- **A team keeps at least one owner.** A trigger enforces it, so deleting a user who is a team's only
  owner fails until ownership is transferred.
- **Uniqueness is per team.** `documents.sha256` becomes `UNIQUE (team_id, sha256)`, so two teams can
  each upload the same SOP. The new index is built before the old constraint is dropped.
- **Foreign keys are added `NOT VALID`.** They take only a brief lock, and 003 validates existing rows
  under a lock that allows writes.

## 2. Indexing & performance

### Policies cost one evaluation per statement, not one per row

Every policy has the form:

```sql
team_id = ANY ((SELECT smartlab.team_ids('viewer'))::integer[])
```

`smartlab.team_ids()` returns the caller's team ids as an array. The scalar sub-select becomes an
**InitPlan**: it's computed once, then compared per row as `team_id = ANY ($0)`, which can use an
index (asserted in `test_policies_evaluate_membership_once_per_statement`).

> **Gotcha found in testing.** Without the `::integer[]` cast, `ANY ((SELECT …))` is parsed as
> `ANY (subquery)`, and the policy fails to create with `operator does not exist: integer = integer[]`.

Write policies are one per command, never `FOR ALL`. A `FOR ALL` policy also applies to SELECT, and
PostgreSQL ORs permissive policies, so every row from another team would be probed twice (seen in the
plans; asserted by `test_child_table_reads_probe_the_parent_once_per_row`).

### Indexes (`003_indexes.sql`)

Every index leads with `team_id`, followed by the column the endpoint filters or sorts on. Examples:
`documents (team_id, updated_at DESC, id DESC)`, `reagents (team_id, expiry_date, id)`,
`chat_messages (team_id, session_id, id)`, `audit_log (team_id, created_at)`, and a partial
`troubleshooting (team_id, error_code) WHERE verified = 1`. The `organization_id` foreign key on users
is indexed (`team_ids()` joins on it), and `team_memberships` has `(user_id)` alongside its
`(team_id, user_id)` primary key.

> **Observed in the plans.** RLS alone gives `team_id = ANY ($0)`, which uses an index's team prefix
> but not its sort order: `documents ORDER BY updated_at` showed an index scan followed by a Sort. The
> ordered `(team_id, updated_at)` scan needs the app's own `WHERE team_id = ?`, which the Flask plan
> adds to every query anyway. RLS is the backstop, and the explicit predicate is what the indexes
> serve.

### Vector search (`004_pgvector.sql`)

Each `chunk_embeddings` row stores `team_id`, derived by trigger from the chunk's document and immutable
because the document's is. An HNSW index (`vector_cosine_ops`, m = 16, ef_construction = 64) covers the
embeddings, with a B-tree on `team_id`. `smartlab.match_chunks(query, k, document_ids)` runs under the
caller's RLS and picks a strategy per call:

| Scope | Strategy | Why |
|---|---|---|
| Team < 10,000 vectors, or explicit `document_ids` | Exact: team index, then rank | HNSW filters *after* finding neighbours. For a small team it walks most of the graph. |
| Larger | HNSW with `hnsw.iterative_scan = relaxed_order` | Keeps scanning until k rows pass the team filter. A plain scan returns fewer than k. |

Measured with 20,000 vectors, k = 10, every result set the right size and team:

| Team | HNSW only | With the split (cold / warm median) |
|---|---|---|
| 12 vectors | 69 ms cold | 16 ms / 8 ms |
| 20,000 vectors | 11 ms cold | 16 ms / 8 ms |

Dimension 384 matches the production model (`all-MiniLM-L6-v2`). The 2048-dimension offline hashing
embedder exceeds HNSW's 2000-dimension limit for `vector`, so it stays on the in-process index.
Requires pgvector ≥ 0.8 for iterative scans; Supabase has it.

### Connections and pooling

- `set_config(…, true)` is transaction-local, so it's safe behind both Supavisor modes: session
  (port 5432, today's `.env.example`) and transaction (port 6543). Session-level `SET` would leak
  identities between requests in transaction mode.
- `smartlab_app` gets `statement_timeout = 15s`.
- **`idle_in_transaction_session_timeout` is deliberately not set.** A co-pilot request holds its
  transaction open while it waits up to 90 s for Claude, and a short timeout would kill those
  connections.
- Pool size: `DB_POOL_MAX` (24) × `WEB_CONCURRENCY` (1) must stay under the plan's pooler limit.
- Through Supavisor, the custom role logs in as `smartlab_app.<project-ref>`.

### N+1 patterns found while indexing (current code)

| Where | Pattern | Fix |
|---|---|---|
| `api/data.py` `list_datasets` | Loads every dataset's full `rows_json` just to count rows | Store a `row_count` column, or `json_array_length(rows_json::json)` on PG |
| `api/experiments.py` `create_experiment` | `execute()` commits once per step | Insert all steps with `executemany`, then one commit |
| `api/profiles.py` `list_profiles` | 3 correlated sub-selects per profile | One `LEFT JOIN` on grouped aggregates |

## 3. Row-level security

### Identity model

```
Flask request ─▶ smartlab_app (NOBYPASSRLS)
                 set_config('smartlab.user_id', '42', true)   ← trusted only when session_user = smartlab_app
                 set_config('smartlab.team_id', '7',  true)   ← optional; can only narrow, so trusted from anyone
Supabase JWT  ─▶ authenticated: auth.uid() ─▶ users.auth_user_id ─▶ account id
Owner (postgres): migrations, init_schema, seeding ─▶ bypasses RLS (FORCE RLS is not used)
```

`smartlab.current_user_id()` trusts the setting only when the **login** role (`session_user`) is
`smartlab_app`. That holds inside `SECURITY DEFINER` functions, and a client can't change it with
`SET ROLE`. A Supabase Auth client that sets `smartlab.user_id` is still identified by its JWT
(`test_only_the_app_role_can_assert_a_user_id`).

Effective team roles:

- **Explicit membership** gives `viewer < member < admin < owner`.
- **Org admins** (`users.role = 'admin'`) are owners of every team in their organization.
- **Pinning a team** (`smartlab.team_id`) restricts every table to that team, even for org admins.

### Policy matrix

| Table | SELECT | INSERT / UPDATE | DELETE |
|---|---|---|---|
| documents, reagents, troubleshooting, equipment, projects | viewer | member | **admin** |
| experiments, datasets, comments, shared_files | viewer | member | member |
| chat_messages, agent_uploads | viewer | **viewer** (viewers can ask questions) | member |
| chunks, experiment_steps/variables, reviews | via parent: viewer | via parent: member | via parent: member |
| answer_feedback | via message: viewer | insert viewer, **update (resolve) admin** | viewer, open flags only |
| audit_log, agent_runs | viewer (team-less audit rows: org admins) | insert only | **never** (no policy, `REVOKE`, trigger) |
| teams | members, plus org admins for their org | insert: org admin; update: team admin | never (archive) |
| team_memberships | team members, or your own row | team admin, **never above their own role**, same org only | team admin, or yourself (leave) |
| organizations | your own | never | never |
| users, auth_sessions, password_resets, profiles, settings, compounds | `smartlab_app` only (login runs before identity is known) | same | same |

`anon` and `authenticated` lose all table privileges, closing the Supabase Data API path. Every
`smartlab.*` function has `EXECUTE` revoked from `PUBLIC`.

The core helper:

```sql
CREATE OR REPLACE FUNCTION smartlab.team_ids(p_min_role text DEFAULT 'viewer') RETURNS integer[]
LANGUAGE sql STABLE SECURITY DEFINER SET search_path = '' AS $$
    SELECT COALESCE(array_agg(t.id ORDER BY t.id), '{}')
      FROM public.teams t
      JOIN public.users u ON u.id = smartlab.current_user_id() AND u.organization_id = t.organization_id
      LEFT JOIN public.team_memberships m ON m.team_id = t.id AND m.user_id = u.id
     WHERE t.archived_at IS NULL
       AND (smartlab.current_team_id() IS NULL OR t.id = smartlab.current_team_id())
       AND smartlab.role_rank(CASE WHEN u.role = 'admin' THEN 'owner' ELSE m.role END)
           >= smartlab.role_rank(p_min_role)
$$;
```

A team table's policies, as generated for `documents`:

```sql
CREATE POLICY documents_select ON public.documents FOR SELECT
    USING (team_id = ANY ((SELECT smartlab.team_ids('viewer'))::integer[]));
CREATE POLICY documents_insert ON public.documents FOR INSERT
    WITH CHECK (team_id = ANY ((SELECT smartlab.team_ids('member'))::integer[]));
CREATE POLICY documents_update ON public.documents FOR UPDATE
    USING (team_id = ANY ((SELECT smartlab.team_ids('member'))::integer[]))
    WITH CHECK (team_id = ANY ((SELECT smartlab.team_ids('member'))::integer[]));
CREATE POLICY documents_delete ON public.documents FOR DELETE
    USING (team_id = ANY ((SELECT smartlab.team_ids('admin'))::integer[]));
```

### What the tests prove

- With no identity, every table returns 0 rows.
- A member sees only their team, including child rows such as chunks and steps.
- A guessed id returns nothing, and an `UPDATE` on it affects 0 rows.
- Pinning narrows an org admin to one team; pinning a foreign team shows nothing.
- Another organization's admin sees none of this org's data.
- Inserting into a foreign team is rejected.
- Viewers can't write, but they can chat.
- Deleting a document needs a team admin, and cascades still work under RLS.
- Audit rows can't be updated or deleted.
- Admins can't grant a role above their own, members can't manage memberships, and accounts from
  another org can't be added.
- The last owner can't be removed.
- Sign-up enrollment works once.
- Org admins can create teams; members can't.
- A spoofed `smartlab.user_id` is ignored for JWT clients.
- `anon` and `authenticated` have no table access.
- Vector search returns k rows from the caller's team only, and an embedding's team can't be forged.

## 4. Backend integration (Python, psycopg2)

The app talks to PostgreSQL through its own `PgConnection` adapter (`backend/app/db.py`), not
SQLAlchemy or supabase-py. supabase-py goes through the Data API and needs Supabase Auth JWTs. The
changes below were exercised against the migrated database as `smartlab_app`:

- inserts return `lastrowid`;
- the binding survives `commit()` and `rollback()`;
- read-only tool connections are scoped and refuse writes;
- sign-up enrollment works;
- unbound connections see nothing.

**a) Two connection URLs.** Boot-time DDL and seeding need the owner. Requests use the restricted role.

```python
# config.py
DATABASE_OWNER_URL = os.getenv("SMARTLAB_DATABASE_OWNER_URL") or _DB_URL  # init_schema + seed (postgres)
# SMARTLAB_DATABASE_URL becomes postgresql://smartlab_app.<project-ref>:<pw>@...pooler.supabase.com:6543/postgres

# __init__.py, create_app()
conn = connect(app.config["DATABASE_OWNER_URL"] if app.config["DATABASE_ENGINE"] == "postgresql"
               else database_target(app.config))
```

**b) `PgConnection` re-declares the caller at the start of every transaction.** A
transaction-local setting would otherwise vanish at the first `commit()`, and `execute()` commits
mid-request.

```python
_TENANT_SQL = "SELECT set_config('smartlab.user_id', %s, true), set_config('smartlab.team_id', %s, true)"
# Append-only logs: nothing reads their lastrowid, and RETURNING would require the caller to be able to
# SELECT the new row back. A team-less audit event (sign-up) cannot pass that check.
_RETURNS_ID = TABLES_WITH_ID - set(APPEND_ONLY_TABLES)


class PgConnection:
    def __init__(self, raw, release=None):
        _register_pg_types()
        self._raw = raw
        self._release = release
        self._tenant: tuple[str, str] | None = None
        self._tenant_pending = False

    def bind_tenant(self, user_id: int | None, team_id: int | None) -> None:
        """Declare who is asking, for row-level security. Re-applied at the start of every transaction."""
        self._tenant = ("" if user_id is None else str(user_id), "" if team_id is None else str(team_id))
        self._tenant_pending = True

    def _cursor(self):
        cur = self._raw.cursor()
        if self._tenant_pending:
            cur.execute(_TENANT_SQL, self._tenant)
            self._tenant_pending = False
        return cur

    def execute(self, sql, params=()):
        params = _adapt_params(params)
        statement = translate_sql(sql, bool(params))
        match = _INSERT_INTO.match(statement)
        wants_id = bool(match) and match.group(1).lower() in _RETURNS_ID and not _RETURNING.search(statement)
        if wants_id:
            statement = statement.rstrip().rstrip(";") + " RETURNING id"
        cur = self._cursor()  # also in executemany() and executescript()
        cur.execute(statement, params or None)
        lastrowid = cur.fetchone()[0] if wants_id else None
        return PgCursor(cur, lastrowid, consumed=wants_id)

    def commit(self) -> None:
        self._raw.commit()
        self._tenant_pending = self._tenant is not None

    def rollback(self) -> None:
        self._raw.rollback()
        self._tenant_pending = self._tenant is not None

    # close(): also set self._tenant = None. The setting itself already ended with the transaction.
```

**c) Bind wherever a connection serves a user.**

```python
# tenancy.py: last line of resolve_team(), once g.user and g.team are verified
db = get_db()
if is_postgres(db):
    db.bind_tenant(g.user["id"] if g.user else None, g.team["id"])

# api/chat.py chat_stream(): the worker thread opens its own connection
tenant = (_user_id(), team_id())                     # captured in the request
def work():
    with app.app_context():
        get_db().bind_tenant(*tenant)                  # before persist_run()

# agents/tools.py ToolEnv.from_app(): read-only tool connections
def open_conn():
    conn = connect_readonly(target, pool)
    if is_postgres(conn):
        conn.bind_tenant(user_id, team_id)
    return conn

# api/auth.py signup(): the one membership the app role may create without being a team admin
if is_postgres(conn):
    conn.execute("SELECT smartlab.enroll_in_default_team(?)", (user_id,))
else:
    conn.execute("INSERT INTO team_memberships (team_id, user_id, role) VALUES (?, ?, ?)",
                 (current_app.config["DEFAULT_TEAM_ID"], user_id, "owner" if role == "admin" else "member"))
```

**d) Vector search through RLS** (for a future `PgVectorStore` behind `rag/vector_store.py`):

```python
def search(conn, query_vec: "np.ndarray", k: int, document_ids: list[int] | None = None) -> list[tuple[int, float]]:
    literal = "[" + ",".join(f"{x:.6f}" for x in query_vec) + "]"
    rows = conn.execute("SELECT chunk_id, similarity FROM smartlab.match_chunks(?::extensions.vector, ?, ?)",
                        (literal, k, document_ids)).fetchall()
    return [(r["chunk_id"], float(r["similarity"])) for r in rows]
```

## Rollout

RLS goes live through a connection-string change, which makes it reversible in seconds:

| # | Step | Effect on the running app | Rollback |
|---|---|---|---|
| 0 | Back up; run all migrations on a Supabase branch and run the test suite against it | — | — |
| 1 | `001_tenancy.sql`, then `003_indexes.sql` with `psql -f` | None (tested with today's code) | Drop the new columns and tables |
| 2 | Deploy team-aware app code (section 4), still connecting as owner | Owner bypasses RLS; `bind_tenant` is harmless | Redeploy |
| 3 | `002_rls.sql`; `ALTER ROLE smartlab_app PASSWORD '…'` | None while the app connects as owner | Drop the policies |
| 4 | Set `SMARTLAB_DATABASE_OWNER_URL` = the old URL and `SMARTLAB_DATABASE_URL` = `smartlab_app`; restart | **RLS enforced** | Swap the URLs back |
| 5 | Optional: `004_pgvector.sql` plus a `PgVectorStore` | — | Keep the FAISS backend |
